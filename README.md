# Crypto & Currency Portfolio Tracker (Async FastAPI + PostgreSQL)

Асинхронный высокопроизводительный бэкенд-сервис на базе FastAPI и PostgreSQL, разработанный специально для ведения крипто-портфелей. Проект демонстрирует применение продвинутых архитектурных паттернов, строгое обеспечение финансовой точности расчетов, а также разделение ввода-вывода (I/O-bound) и тяжелых вычислений (CPU-bound) по разным системным процессам.

## 🛠 Технологический стек
* **Язык разработки:** Python 3.14
* **Веб-фреймворк:** FastAPI (0.143.0), Uvicorn
* **Валидация данных:** Pydantic v2 (2.14.0), Pydantic-settings
* **СУБД & ORM:** PostgreSQL 16, SQLAlchemy 2.1 (асинхронный движок), Asyncpg
* **Параллелизм & Конкурентность:** Asyncio (httpx.AsyncClient), concurrent.futures.ProcessPoolExecutor
* **Тестирование:** Pytest (9.1.1), pytest-asyncio
* **DevOps:** Docker, Docker Compose

## 🏗 Архитектурные особенности и ключевые решения

### 1. Сквозная финансовая точность (Банковский стандарт)
Все финансовые поля (объемы активов в `portfolios`, цены в `currencies` и баланс в `user_profiles`) спроектированы с использованием типа данных `Numeric` в SQLAlchemy, переходящего в `DECIMAL` на уровне СУБД. Валидация на входе и выходе завязана строго на тип `Decimal` в Pydantic. Это полностью исключает накопление микропогрешностей округления, свойственных типу `float`.

### 2. Защита от N+1 и ошибок контекста (MissingGreenlet)
Для выгрузки связанных сущностей в асинхронной среде ORM внедрена стратегия жадной загрузки (Eager Loading):
* `joinedload` — для связей Один-к-Одному (`User.profile`) и Многие-к-Одному (`Portfolio.currency`).
* `selectinload` — для связей Один-ко-Многим (`User.portfolio_assets`).

Это гарантирует сборку комплексных JSON-ответов ровно за 1 эффективный SQL-запрос `JOIN`.

### 3. Неблокирующий фоновый парсер (I/O-bound)
Скрипт `src/services/parser.py` в бесконечном цикле собирает актуальные курсы валют по сети через асинхронный клиент `httpx` и обновляет их в PostgreSQL методом Upsert. Задача запущена как `asyncio.create_task()` внутри жизненного цикла приложения (`lifespan`). Каждая итерация парсера создает изолированную сессию, исключая конфликты параллельных транзакций.

### 4. CPU-bound аналитика на процессах
Тяжелые математические вычисления (расчет диверсификации, симуляция волатильности на миллионы итераций) полностью изолированы от основного Event Loop. Через `loop.run_in_executor()` задача распределяется по ядрам процессора внутри `ProcessPoolExecutor`. Основной поток FastAPI остается 100% свободным для обработки входящих HTTP-запросов.

### 5. Безопасность на уровне СУБД и транзакций (ACID)
Эндпоинты создания и обновления данных (регистрация пользователя, депозиты кошелька) защищены строгими блоками атомарных транзакций СУБД с автоматическим и ручным контролем `commit / rollback`. На таблицы повешены уникальные индексы ограничения (`unique=True`), а также композитный составной B-Tree индекс на связку `(user_id, currency_id)` для мгновенного поиска активов.

### 6. Изолированная среда автоматического тестирования
Развернута масштабируемая тестовая инфраструктура на Pytest, которая перед началом тестов автоматически разворачивает в PostgreSQL чистую независимую базу данных `test_crypto_tracker_db`, накатывает таблицы, симулирует HTTP-запросы через `AsyncClient` и гарантирует полную изоляцию Event Loop (`loop_scope="session"`) для стабильной работы пула `asyncpg`.

## 🚀 Как запустить проект локально

### 1. Подготовка переменных окружения
Создайте в корне проекта файл **`.env`** и заполните его вашими параметрами для базы данных:

```env
DB_USER=postgres_user
DB_PASSWORD=my_secure_password
DB_NAME=crypto_tracker_db
```

### 2. Сборка и запуск оркестра контейнеров
Выполните команду сборки образа и запуска контейнеров в фоновом режиме:

```bash
docker compose up --build -d
```
Docker создаст изолированную сеть `tracker_network`, поднимет PostgreSQL, смонтирует постоянный том `postgres_data` для вечного хранения записей, а веб-сервер при старте автоматически создаст необходимые таблицы в СУБД и запустит фоновый парсер.

### 3. Интерактивная документация Swagger
После успешного запуска перейдите в браузере по адресу:
```text
http://localhost:8000/docs
```
Вам откроется интерактивный UI-интерфейс, откуда можно отправлять реальные запросы на регистрацию, авторизацию, делать депозиты в кошелек и смотреть графики многопроцессорной аналитики.

## 🧪 Запуск автоматических тестов
Запуск тестов происходит внутри изолированной среды Docker-контейнера `web`, где развернуты все системные зависимости. Откройте новый терминал и выполните:

```bash
docker compose exec web pytest -v
```
Тестовый модуль поднимет сессионный Event Loop, создаст временную СУБД `test_crypto_tracker_db`, прогонит поочередно всю цепочку эндпоинтов (с проверкой атомарности транзакций, хэшей и параллельных процессов), выведет детальный отчет и полностью зачистит за собой структуры базы данных.
